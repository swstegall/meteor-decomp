# VfxLogTagId (CDev.Engine.Vfx log-category enum)

**Discovered**: 2026-05-24 by agent-0 while matching FUN_00414fc0

**Purpose**: Numeric category-id → tag-name lookup used by the CDev.Engine.Vfx
logging subsystem. Each tag is a dotted-component string under the
`CDev.Engine.Vfx.*` namespace identifying which subsystem the log line
came from (Must / Instance / Common / Stl / Qix / Framework / ...).

**Lookup fn**: FUN_00414fc0 @0x00014fc0 — `__cdecl const char*(int category_id)`.
The function materialises a 20-slot pointer table on the stack from
.rdata string literals and does a 4-way range dispatch.

## Category-id space

The id space is sparse — different subsystem clusters live in their own
numeric band so the lookup can use simple range checks rather than a
hash or jump table.

| id range    | meaning                                            |
|-------------|----------------------------------------------------|
| 0x00..0x03  | `Must`, `MustFix`, `MustTemporary`, `Unhandled` (assertion-/diagnostic-grade tags) |
| 0x04..0x07  | Aliases for the 0x60..0x65 `Framework.CDev*` cluster (only 4 of the 6 — `Framework.CDev`, `Framework.CDev.Cut`, `Framework.CDev.Lay`, `Framework.CDev.Fw`) |
| 0x08..0x11  | Core engine tags: `Instance`, `Common`, `Stl`, `Qix`, `BaseControl`, `QixControl`, `IntermediateResource`, `ResourceLoader`, `VfxResourceFormat`, `VfxResourceModel` |
| 0x12        | (dead — would read past stack frame; UB)           |
| 0x60..0x65  | Framework cluster: `Framework.CDev`, `Framework.CDev.Vfx`, `Framework.CDev.Dw`, `Framework.CDev.Cut`, `Framework.CDev.Lay`, `Framework.CDev.Fw` |
| 0x80..0xbf  | `Application` (caller-supplied app-level tags, all bucket to one name) |
| anything else | `Unknown` (fallback)                              |

The 0x04..0x07 alias band is curious — id 4 returns `Framework.CDev`
which is also the 0x60 entry. The aliases let calling code use a single
small-int range (0..7) instead of mixing 0..3 and 0x60..0x65 if it
doesn't need to distinguish.

Note that the 4-way dispatch in arm 2 (id <= 0x12) reads
`[esp + (id+2)*4]`, which for id=0x12 would land on the saved return
address (the frame is exactly 0x50 bytes). This is harmless — Vfx
callers presumably never pass 0x12 — but it's a latent UB if anyone
ever does.
