# SQEX::CDev::Engine::Memory::Alternative::SystemHeapSpace

**Discovered**: 2026-05-24 by agent-5 while matching FUN_00414b50 (0x00014b50).

A concrete heap-space implementation in the `SQEX::CDev::Engine::Memory::Alternative`
namespace. Multi-inherits from `ISpace` (primary base) plus three secondary
interfaces — exposed through embedded sub-object vftables at fixed offsets.

## Vftables observed (resolved by the dtor body)

| Offset (in `this`) | Sub-object              | vftable VA  |
|--------------------|-------------------------|-------------|
| 0x00 (primary)     | SystemHeapSpace (full)  | 0x00f5701c  |
| 0x00 (after reset) | ISpace (base, chain-up) | 0x00f566fc  |
| 0x20 (this[0x08])  | Link                    | 0x00f567c4  |
| 0x34 (this[0x0d])  | IDebugSpace             | 0x00f567b4  |
| 0x3c (this[0x0f])  | IDebugBlock             | 0x00f56788  |

The primary-base vftable is rewritten **twice** by the dtor: first to
`SystemHeapSpace::vftable` (so virtual calls during the body of the dtor
dispatch to the most-derived overrides), and at the end to
`ISpace::vftable` so that the chain-up to the base destructor sees the
correct slice. This is the standard MSVC "vtable rewinding" idiom for
class-hierarchy destructors.

## Layout (inferred from the dtor)

| Offset | Field            | Notes                                              |
|--------|------------------|----------------------------------------------------|
| 0x00   | primary vftable  | dispatched as SystemHeapSpace during dtor body     |
| 0x08   | CRITICAL_SECTION | `DeleteCriticalSection(&this->cs)` at end of dtor  |
|        |                  | sizeof CRITICAL_SECTION on Win32 = 24 bytes        |
|        |                  | → spans 0x08–0x1f                                  |
| 0x20   | Link vftable     | embedded `Link` sub-object starts here             |
| 0x24   | Link.prev        | `prev` pointer in intrusive doubly-linked list     |
| 0x28   | Link.next        | `next` pointer in intrusive doubly-linked list     |
| 0x34   | IDebugSpace vt   | embedded interface sub-object                      |
| 0x3c   | IDebugBlock vt   | embedded interface sub-object                      |

The doubly-linked-list unlink performed by the dtor is canonical:
```
prev->next = next   ; *(this->Link.prev + 8) = this->Link.next
next->prev = prev   ; *(this->Link.next + 4) = this->Link.prev
```
which establishes that `Link` itself has layout
`{ vftable@+0, prev@+4, next@+8 }` (i.e. its prev/next live at offset
+4 and +8 within the Link sub-object, not within the enclosing
SystemHeapSpace — the +0x24 / +0x28 values seen in the dtor are
`this+0x20+0x4` and `this+0x20+0x8`).
