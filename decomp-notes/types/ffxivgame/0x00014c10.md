# Refcounted "init-once" singleton trio @ 0x01328040 — layout

Discovered while matching `FUN_00414c10` @ 0x00014c10 — the refcount-
guarded init shim for a process-wide singleton whose underlying init
body is a `_time64`/`srand` pair (FUN_00414df0, reached via the 5-byte
JMP-thunk FUN_00414d60).

## Globals trio (in `.data`, 0x01328040 / 0x01328044 / 0x01328058)

| RVA          | Type   | Role                                                  |
|--------------|--------|-------------------------------------------------------|
| `0x01328040` | `int`  | refcount; 0 means "init not yet run"                  |
| `0x01328044` | object | singleton storage; passed as `this` (ECX) to the init |
| `0x01328058` | `char` | captured init flag (param->byte_at_+8 on first call)  |

The three globals appear close enough in `.data` to be members of a
single struct, but only the refcount/ECX-base pair (`0x01328040` and
`0x01328044`) sit adjacent — the captured byte at `0x01328058` is 0x14
bytes further along, so this may be a real struct or three sibling
globals laid out by the linker's `.data` packer.

## Two collaborating shims around the trio

| RVA          | Symbol         | Role                                              |
|--------------|----------------|---------------------------------------------------|
| `0x00014bf0` | `FUN_00414bf0` | Constructs the `Param` arg on the caller's stack: |
|              |                |   fields 0/4 zeroed, byte at +0x8 set to 1.       |
| `0x00014c10` | `FUN_00414c10` | __cdecl shim: if refcount == 0 capture the byte   |
|              |                | flag and invoke the singleton's init; always      |
|              |                | bumps refcount.                                   |
| `0x00014d60` | `FUN_00414d60` | 5-byte JMP-thunk → `FUN_00414df0`. Called via     |
|              |                | __thiscall (ECX = &singleton@0x01328044), but     |
|              |                | the target is a __cdecl `void()`; ECX is unused.  |
| `0x00014df0` | `FUN_00414df0` | The actual init body: `_time64(&t); srand(t);`    |

Composition pattern (re-derived from the asm shape; structurally
equivalent to MSVC's `std::ios_base::Init` lazy-init scheme):

```cpp
extern int  g_refcount;     // 0x01328040
extern Foo  g_singleton;    // 0x01328044  (this for Foo::Init)
extern char g_flag;         // 0x01328058

struct Param { int f0; int f4; char f8; };

void FUN_00414bf0(Param* p) {     // __thiscall (ECX = p)
    p->f0 = 0;
    p->f4 = 0;
    p->f8 = 1;
}

void FUN_00414c10(Param* p) {     // __cdecl
    if (g_refcount == 0) {
        g_flag = p->f8;
        g_singleton.Init();       // thiscall via 5-byte JMP-thunk
    }
    ++g_refcount;
}
```

## Asm shape (40 B)

```
00014c10: 83 3d 40 80 32 01 00       cmp dword ptr [01328040], 0
00014c17: 75 17                       jne short skip
00014c19: 8b 44 24 04                 mov eax, [esp+4]
00014c1d: 8a 48 08                    mov cl,  [eax+8]
00014c20: 88 0d 58 80 32 01           mov [01328058], cl
00014c26: b9 44 80 32 01              mov ecx, offset 01328044
00014c2b: e8 30 01 00 00              call FUN_00414d60     ; JMP-thunk
00014c30: skip:
00014c30: 83 05 40 80 32 01 01        add [01328040], 1
00014c37: c3                          ret
```

MSVC /O2 picks CL specifically for the byte transfer because the next
instruction overwrites ECX with `offset &singleton` for the thiscall —
this is the canonical "reuse-the-soon-to-be-clobbered-reg-half" trick.

## Caller context

Sole caller observed is `FUN_00a55660` (Ghidra-decomp shows it stamping
`SQEX::CDev::Engine::Fw::Framework::Physics::PhysicsManager::vftable`
into `*in_ECX`, then calling `FUN_00414bf0()` followed by
`FUN_00414c10(&param)`). The caller-side construction of a transient
9-byte `Param` immediately before the shim call confirms the
__cdecl/by-pointer interpretation here.
