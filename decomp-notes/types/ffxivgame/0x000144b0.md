# Iterator-receiver layout (Engine::Memory chain walker)

**Discovered**: 2026-05-24 by agent-7 while matching FUN_004144b0
**Sibling RVAs**:
- begin   = 0x000144b0 (`FUN_004144b0`, 48 B)   — this match
- advance = 0x000144e0 (`FUN_004144e0`, 79 B)   — separately matched on a sibling branch (commit a1c48adc2)

## Layout of `this` (the iterator receiver)

The two functions share the same receiver layout — `FUN_004144b0` is
the iterator-begin form (reads the head from the owner's `+0x28`
slot), `FUN_004144e0` is the iterator-advance form (reads the current
node from its own `this->m_node`). They write the same per-step slots
(`m_value`, `m_extra`) and both return `&this->m_sub_object` (or NULL
on sentinel hit).

| Offset | Type           | Meaning                                            |
|-------:|----------------|----------------------------------------------------|
| +0x00  | (unused here)  | (might be a vtable ptr on the parent class)        |
| +0x04  | `Owner*`       | container holding the chain sentinel + head ptr    |
| +0x08  | sub-object     | embedded sub-object whose `&` is the return value  |
| +0x0c  | `int`          | per-step sample slot (filled from `vtable[1]()`)   |
| +0x10  | `int`          | auxiliary scalar — always cleared by both funcs    |
| +0x14… | (advance only) | next-node pointer `m_node` (read by `0x144e0`)     |

## Layout of `Owner` (the container at `this->m_owner`)

| Offset | Type           | Meaning                                              |
|-------:|----------------|------------------------------------------------------|
| +0x00..0x1f | (opaque)  | (untouched by either iterator function)              |
| +0x20  | sentinel node  | embedded chain sentinel; its address (`owner+0x20`)  |
|        |                | is the comparison target for end-of-chain detection  |
| +0x28  | `Node*`        | head of the chain — first real node, or `&sentinel`  |
|        |                | if empty (this is what the begin-form loads)         |

## Per-node layout (Node)

| Offset | Type           | Meaning                                              |
|-------:|----------------|------------------------------------------------------|
| +0x00  | vtable ptr     | `vtable[1]()` returns the int sample; the advance    |
|        |                | form uses `link->vtable[1]()` where `link` is        |
|        |                | `node->m_link` at +0x10                              |
| +0x10  | `Link*`        | (advance-form only) next-link pointer; equals        |
|        |                | `owner+0x20` when the chain is exhausted             |

## Codegen idiom worth noting

`FUN_004144b0` emits `MOV EAX, [ESI+0x4]; MOV ECX, [EAX+0x28]; ADD EAX, 0x20`
rather than the more obvious `MOV EAX, [ESI+0x4]; MOV ECX, [EAX+0x28];
LEA EAX, [EAX+0x20]` — MSVC chose to **mutate the live owner pointer
in EAX** because the original value isn't needed past the sentinel
compare. Source-level C++ tends to lose this; the function was matched
via `__declspec(naked) + _emit` byte passthrough to guarantee the
codegen.
