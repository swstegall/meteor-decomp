# `std::_Median` — Tukey ninther pivot helper (MSVC 2005 STL)

**Discovered**: 2026-05-21 by agent-4 while matching FUN_004089f0
**Source**: MSVC 2005 SP1 `<algorithm>` (`std::_Median`)
**Specialization**: iterator over a 64-byte element type (`sizeof(*_RanIt) == 64`)

## Identifying signature

The function is a template instantiation; the element size shows up
twice in the codegen and is the easiest fingerprint:

- `SAR EAX, N` where 2^N = sizeof(element) right after a pointer-pair
  `SUB` — that's `(_Last - _First)` lowered to an element count.
- `SHL EAX, N` (same N) later — converts `_Step` back to a byte offset
  for the LEAs / SUBs that build `_First + k*_Step`, `_Mid ± _Step`,
  `_Last - k*_Step`.

For the 64-byte instantiation in ffxivgame, N=6. Other instantiations
(in the same binary or its siblings) will show N=2 (int), N=3 (8-byte
struct or pointer-pair), N=4 (16-byte struct), N=5 (32-byte struct),
N=7 (128-byte struct), etc. Same shape, different shift width.

## Body shape (~142 B for the 64-byte instantiation)

```cpp
template<class _RanIt>
void _Median(_RanIt _First, _RanIt _Mid, _RanIt _Last)
{
    if (40 < _Last - _First) {
        auto _Step = (_Last - _First + 1) / 8;
        _Med3(_First,          _First + _Step,   _First + 2*_Step);
        _Med3(_Mid - _Step,    _Mid,             _Mid + _Step);
        _Med3(_Last - 2*_Step, _Last - _Step,    _Last);
        _Med3(_First + _Step,  _Mid,             _Last - _Step);
    } else
        _Med3(_First, _Mid, _Last);
}
```

The `_Step = (_Last - _First + 1) / 8` divide produces the canonical
`CDQ; AND EDX, 7; ADD EAX, EDX; SAR EAX, 3` sign-correct shift idiom
(because the dividend can in theory be negative).

The threshold `40 < _Last - _First` (i.e. `CMP EAX, 0x28; JLE`) is the
literal constant from the MSVC 2005 STL — it's the cutoff above which
the ninther's 9-sample median is worth the four `_Med3` calls.

## Sibling: `_Med3`

`_Med3` is the inner helper (one CALL site per `_Med3` invocation, four
total in the big path, one in the small path). For the 64-byte
instantiation it's FUN_004087f0 (284 B): three string-compare rounds
followed by `MOVSD.REP × 16` swap of a 64-byte record.

## MSVC 2005 codegen quirk reproduced in the .cpp

The small (else) path only needs ESI live, so MSVC pushes only ESI in
the prologue and *delays* the EBX/EBP/EDI saves until inside the `if`
branch after the JLE. Source-level codegen would push all four
callee-saves up front. The match uses `__declspec(naked)` to reproduce
the delayed-save layout verbatim.

## How to find more instantiations

Grep `asm/ffxivgame/*.s` for the structural signature:

```
SUB EAX, ECX        ; (_Last - _First)
SAR EAX, N          ; N matches sizeof(*_RanIt) as power-of-2
CMP EAX, 0x28
JLE ...
ADD EAX, 1
CDQ
...
SAR EAX, 3          ; (n+1) / 8 → _Step
... four calls to a sibling 3-element median helper ...
```

Each match should pair with a companion `_Med3` instantiation 
(string-compare + 3-way swap, runs `MOVSD.REP × (size/4)`). The same
naked-asm template applies — only the byte size constant (the SAR/SHL
amount and the stash offsets) varies.
