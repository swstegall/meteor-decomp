# FUN_00414790 — `__cdecl` factory for the FUN_00414640 in-place-init object

**Discovered**: 2026-05-24 while matching FUN_00414790 (RVA 0x00014790, 32 B).

This is a thin factory wrapper paired with the in-place initialiser at
RVA 0x00414640. The same pattern recurs across the binary (cf.
FUN_00414580 / 0x00014580.md), so the per-class factory + ctor split is
the canonical idiom for `SQEX::CDev::Engine::Memory::Alternative::*`
heap-block style objects in ffxivgame.

## Factory signature

```
ObjT * __cdecl FUN_00414790(undefined4 param_1);
```

`__cdecl`, one stack arg, returns `EAX`. No frame (/Oy). Returns the
freshly-constructed object on success, NULL on alloc failure.

## Behaviour

1. `__aligned_malloc(0x48, 0x10)` — allocates 72 B on a 16-B boundary.
2. If NULL, returns NULL (skips the init call entirely — *unlike* the
   FUN_00414580 factory which calls the backing-buffer alloc
   unconditionally).
3. Otherwise calls `FUN_00414640(this = alloc, arg = param_1)` as
   `__thiscall`. FUN_00414640 ends `MOV EAX,ESI / POP ESI / RET 4`
   (returns its `this`), so the factory's tail `RET` propagates the new
   object pointer back to the caller.

## What this confirms about FUN_00414640

```
Obj * __thiscall FUN_00414640(Obj *this /* ECX */, undefined4 arg /* [ESP+4] */);
```

- `__thiscall`: `ECX = this`, one stack arg, `RET 4` cleans it.
- Returns `this` in EAX (classic ctor-returns-this idiom).
- Instance size: **0x48 bytes** (from the factory's alloc size). The
  alignment requirement is **16** (from the alignment arg passed to
  `__aligned_malloc`).
- The single arg `param_1` is threaded directly through — FUN_00414640
  presumably stores it into a field on the new object (a parent / owner
  pointer, based on the FUN_00414580 SystemHeapBlock layout where the
  caller's ECX lands at `+0x14`).

## Identifying signature

The 32-byte body is fingerprinted by the `6a 10 6a 48 e8 ?? ?? ?? ?? 83 c4 08`
prologue (PUSH 0x10 / PUSH 0x48 / CALL __aligned_malloc / ADD ESP,8) — the
0x48 immediate is unique enough among `__aligned_malloc(N, 0x10)` call
sites in this binary to distinguish this factory from its siblings
(0x3c → FUN_00414580 SystemHeapBlock, 0x48 → here).

The trailing `74 0d ... c3 33 c0 c3` shape (early-return-on-NULL with the
zero-EAX path at the tail) plus the `8b 4c 24 04 / 51 / 8b c8` reload of
the caller arg into ECX (rather than `push dword ptr [esp+4]`) is the
MSVC 2005 /O2 register-allocation choice for "load-then-push" cdecl
arg-forwarding into a thiscall.
