# VfxLogger (provisional name) + g_indent_table

**Discovered**: 2026-05-24 by agent-5 while matching FUN_004154f0 (0x000154f0).

The `__thiscall` formatter at this RVA is a category-tagged log-line
builder ("[vfx]" / "[vfx.w%d]" / "[vfx.assert]") that indents each
message according to a per-instance nesting depth. Two reusable
artifacts come out of this match: the global indent table at .data
0x01265f48 and the lone `this`-relative member at +0x80 that selects
into it.

## Indent table — `g_indent_table` @ .data 0x01265f48

Eight `const char*` entries, one per nesting depth 0..7. Each entry is
a leading-whitespace string two spaces wider than the previous; index 0
is the empty string. Almost certainly `/GF`-pooled — every `[vfx]`-
format consumer in the .text section likely loads from this same table
via the `[ECX*4 + 0x01265f48]` moffs32 idiom.

| Index | VA          | String literal     |
|-------|-------------|--------------------|
| 0     | 0x00f54d48  | `""`               |
| 1     | 0x00f5750c  | `"  "`             |
| 2     | 0x00f57504  | `"    "`           |
| 3     | 0x00f574fc  | `"      "`         |
| 4     | 0x00f574f0  | `"        "`       |
| 5     | 0x00f574e4  | `"          "`     |
| 6     | 0x00f574d4  | `"            "`   |
| 7     | 0x00f574c4  | `"              "` |

The strings live in a single contiguous .rdata island just below the
table. Index 0 is sourced from a deduplicated empty-string constant
that's reused all over the binary (the same 0x00f54d48 you see in any
"empty string default" load), while indices 1–7 are the eight-character-
strided indent prefixes.

## `this`-relative layout (partial)

The format method touches exactly one member: a single byte at +0x80
holding the current nesting depth. The remaining 0x80 bytes below it
plus whatever lives after +0x81 are not exercised by this function.

| Offset | Field          | Notes                                              |
|--------|----------------|----------------------------------------------------|
| +0x80  | uint8 depth    | index into g_indent_table; range observed 0..7     |

The name "VfxLogger" is provisional — picked because all three format
tags ("[vfx]", "[vfx.w%d]", "[vfx.assert]") share the `vfx.` prefix and
this looks like a visual-effects subsystem diagnostic emitter. The
actual class identity can be confirmed once a constructor or RTTI
binding is matched at a sibling RVA.

## Format strings (also `/GF`-pooled)

Three tag templates live as adjacent .rdata strings; the `%s` placeholders
take the indent prefix and the message body.

| VA          | Tag                  | Used by         |
|-------------|----------------------|-----------------|
| 0x00f57524  | `"%s[vfx.w%d] %s"`   | kind == 1       |
| 0x00f57534  | `"%s[vfx.assert] %s"`| kind == 2       |
